# ADR-002: Backend Framework — FastAPI + Python 3.11+

## Status
Accepted

## Context
Backend должен обслуживать:
- REST API для Mini App (Dashboard, History, Settings, Reports).
- Telegram Bot Webhooks через aiogram 3.x (FSM-диалоги).
- Async задачи: генерация отчётов (Pillow/ffmpeg), backup медиа, напоминания.
- Solo-разработчик владеет Python (известный стек из Discovery).
- Бюджет $0-10/мес, pet project, max 100 concurrent users.

## Decision
Использовать **FastAPI** на Python 3.11+.

## Consequences
### Positive
- **Native async/await** — идеально для Telegram webhooks и concurrent API requests.
- **Pydantic** — валидация данных, автоматическая OpenAPI документация, type safety.
- **SQLAlchemy 2.0 async** — полноценный ORM с async поддержкой.
- **Celery + Redis** — async background tasks без блокировки API.
- **APScheduler** — per-user timezone-aware reminders без дополнительных сервисов.
- **aiogram 3.x** — современный async Telegram Bot framework с FSM.

### Negative
- **Меньше batteries included** чем Django — нужно самому настраивать auth, admin, migrations (Alembic).
- **Меньше зрелых библиотек** для некоторых задач (но для pet project достаточно).
- **Сложнее найти готовые шаблоны** для Telegram bot + FastAPI комбинации.

## Alternatives Considered
- **Django + Django REST Framework** — rejected. Sync by default (ASGI поддержка есть, но менее зрелая), тяжелее для бота, ORM sync-only. Для pet project — overkill.
- **NestJS (Node.js)** — rejected. Не входит в known tech stack (соло-разработчик знает Python). Переключение на JS увеличит время разработки.
- **Go (Gin/Echo)** — rejected. Хорош для performance, но solo-разработчик не знает Go. Нет готовых библиотек для aiogram-эквивалента.
- **Flask + Flask-SocketIO** — rejected. Нет native async, менее современный чем FastAPI, менее type-safe.

## Compliance
- GDPR: FastAPI + Pydantic позволяет строгую валидацию и аудит данных.
- Security: async endpoints не блокируют event loop, что предотвращает DoS через slow requests.
